## 两个最要紧的缺陷

### 1. 诊断包仍会漏出明文口令

「导出诊断」会把磁盘日志脱敏后打成一个 zip，用来发给别人协助排障。当自定义密码里带空格时，
归档命令会被整体加引号，写成 `"-pSuper Secret 123"` 这种形式，引号在 `-p` **前面**，
现有脱敏规则一条都匹配不上。我用项目里真实的 .NET 正则跑过五种写法，这种形式原样保留。
上一轮刚补上等号形式，换一个引号位置就又绕过去，说明靠逐条穷举规则容易再漏。
范围不广（程序自己生成的随机密码是十六进制串、不含空格），但一旦发生就是把口令直接交出去。

### 2. 149 项端到端夹具里有一条「永远通过」的断言

夹具脚本用 `check_contains ... "Skipped"` 验证「跳过已处理」策略，而汇总行无论有没有真的跳过
都会固定打印 `Skipped=` 字段名，`Skipped=0` 也算通过。同一脚本还有两处「文件不存在反而判通过」的写法。
约 96/149 项只比退出码，不检查归档是否真的生成、内容是否一致。
后果是：空归档、解压到错目录、跳过策略失效但进程返回 0，都可能绿灯通过。这是验证链可信度问题。

## 其余确认的问题（简述）

- 命令行前置校验与界面口径不一致：缺一个来源就整批退出，界面则是逐项记「未找到」；已修过的「路径末尾带斜杠」缺陷在命令行又回来了（试运行实测可复现）。
- 命令行运行器自己的终端文案完全没本地化，`--lang en` 下错误仍是中文，默认语言又是英文配中文混排。
- 五份帮助都承诺「单独用 `--lang` 直接以该语言启动界面」，实际会被系统语言检测覆盖。
- 命令行 `--shutdown` 只写一行日志，不执行任何关机动作，帮助里却写着会关机。
- 默认串行路径复用同一个可变进度对象，并发路径反而做了克隆保护；界面默认并发度就是 1。
- 页签切换时「压缩」「解压」两个按钮的显隐可能停在上一页状态。
- 两个入口的默认压缩参数不同（压缩级别、恢复记录、分卷）。
- Windows 发布包没有随包 7-Zip 程序，功能依赖用户预装到特定路径；本机测试一条都覆盖不到这个分支。
- 夹具说明文档还写 Debug / 120 项，脚本实际是 Release / 149 项；7 个静态夹具文件引用次数为 0；产物新鲜度没有守卫；界面层没有任何自动化覆盖。

## 需要用户拍板的三件事（完整说明见主报告第六节）

1. **Windows 产物要不要随包带 7-Zip 程序**：现在 Windows 包只有主程序和许可文件，用户没把 7-Zip 装到默认路径时，除 RAR 外所有格式都用不了。选项：随包带 / 放宽查找并给可操作的安装提示 / 只补结构自检。推荐「放宽查找 + 结构自检」。
2. **命令行 `--shutdown` 要不要真的关机**：现在只写日志、不执行，帮助里却承诺会关机。选项：真正执行 / 显式拒绝并改帮助 / 加二次确认开关。推荐「显式拒绝」，因为三个平台的关机命令本机验证不了。
3. **图形界面与命令行的默认参数要不要统一**：压缩级别、恢复记录、分卷三处都不同。选项：统一到一处默认值 / 保持差异但补对照表 / 两边都改为显式必填。推荐「先补对照表，再单独版本统一」。

这三件我都没有替用户决定，也没有在没得到答复前动手改代码。
