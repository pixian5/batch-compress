# 1116-2245 总结

> 用户原问题：**升级 .net sdk11**
> 完成时间：2026-11-16 22:45　版本：`0.8.13` → `0.8.14`

## 结果

已把 .NET SDK 与目标框架升到 11，本机验证链全过：

- SDK：`10.0.403` → **`11.0.100`**（官方脚本并排安装，.NET 10 保留）
- 目标框架：`net10.0` → **`net11.0`**（主工程 + 测试工程）
- Debug / Release：0 警告 0 错误
- 98 项单元测试、42 项经验实测、155 项端到端夹具、4 条界面冒烟、交付冒烟全过
- macOS 打包 `v0.8.14`，后台隐藏运行，`--version` 为 `0.8.14`

## 改了什么

1. `global.json` 固定 `11.0.100`；
2. 两个 csproj 的 `TargetFramework` 改为 `net11.0`；
3. 测试工程移除显式 `Microsoft.Extensions.Logging.Abstractions` 引用，消除 NU1510 警告；
4. `verify.sh` 三处 `bin/Debug/net10.0` 路径改为 `net11.0`；
5. GitHub 工作流步骤名改为“安装 .NET 11 SDK”；
6. README、架构、版本、测试方案、详细设计、经验 07 同步当前版本。

## 升级时踩到的两个点

1. **脚本硬编码旧 TFM 路径**：`verify.sh` 不改会读到旧 Debug 产物，出现“版本还是 0.8.13”的假失败。
2. **NU1510**：.NET 11 共享框架自带 `Logging.Abstractions`，测试工程显式引用被判定冗余；移除即可，不要用 `NoWarn` 掩盖。

## 兼容性说明

- Avalonia 12.1.6 提供 `net10.0`/`net8.0` 资产，`net11.0` 项目会选用 net10 资产，实测全部测试与界面冒烟通过。
- 没有升级 Avalonia、CommunityToolkit.Mvvm、日志库等依赖版本。
- Windows 10 与 Debian 13 未实机跑 .NET 11；三平台云端工作流下一次推送会构建，仅供参考。

## 回滚

还原 `global.json` 版本、两个 csproj 的 `net10.0`、测试工程的 `Logging.Abstractions` 引用、`verify.sh` 的 `net10.0` 路径即可；无数据迁移。
