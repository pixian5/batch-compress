## 二、P4-3 交付内容

### 1. 新服务 `Core/Services/BatchReportService.cs`

- `BatchReportCollector`：复用结构化输出器（NDJSON，逐行 JSON）的「计数增量」判定思路，
  从进度快照收集逐项结果（序号、操作、来源、结果、说明、处理量、耗时），**不改动执行管线**。
- `BatchReportWriter`：输出 CSV（逗号分隔值）或 Markdown 汇总表；
  按扩展名选格式（`.md` / `.markdown` → Markdown，其余 → CSV），自动创建父目录，
  CSV 带 BOM（字节顺序标记）方便表格软件直接打开中文表头。
- **两道防密码保证**：
  ① `IsCommandOutput` 的命令与原始进程输出整条排除（那里才可能有明文密码）；
  ② 万一将来有人把命令文本塞进用户可见消息，正则识别 `-p明文` / `-p 明文` /
  `--password=xxx` 三种写法，把该条消息替换为「（已省略含凭据的文本）」。
  报告**只消费结构化字段，从不读取日志文件或命令日志文本**——这是与批次 16
  诊断包（脱敏日志）的本质区别。

### 2. 命令行 `--report <csv或md路径>`

- 与 `compress` / `extract` 同用，批次结束后写出报告，路径与条目数写日志并提示到标准错误
  （不污染结构化输出的标准输出）。
- 报告是**附加产物**：写失败只记日志与告警，不改变本批次自身的成败退出码。
- 不加入「无界面判定」，单独使用 `--report` 会复用现有的「请指定模式」错误返回 `2`，
  无需新增错误词条。
- 五套帮助文本（简体、繁體、English、日本語、Deutsch）都补了 `--report` 说明。

### 3. 界面「导出本次结果」

- `OperationSession` 持有收集器，进度回调第一行就收集原始快照；
  `MainWindowViewModel` 保留最近一次会话的收集器。
- 新增分部类 `MainWindowViewModel.BatchReport.cs` 与「导出本次结果」按钮，
  导出到桌面 `batchcompress-results-<时间戳>.csv`，并在命令日志与系统通知里给出路径；
  无结果时给出明确提示，不会生成空文件。
- 五语言新增 5 个词条（按钮、提示、无数据、成功、失败），五套字典全部补齐。

### 4. 测试与实测

- 新增 `Program.BatchReportTests.cs`：成功/失败条目、命令输出排除、CSV/Markdown 内容、
  含密码文本省略、按扩展名写文件与自动建目录。测试 **73 → 74 项**全过。
- `测试夹具/经验验证/verify.sh` 新增第 16 项两项断言：带明文密码压缩两个文件后导出报告，
  断言逐项记录齐全且报告内搜不到密码；Markdown 可用、单独 `--report` 返回 `2`。
  实测脚本 **19 → 21 项**全过。
