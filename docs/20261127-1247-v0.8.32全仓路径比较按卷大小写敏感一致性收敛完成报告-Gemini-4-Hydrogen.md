## 背景与问题根因

`0.8.28` 引入了按卷实时检测大小写敏感能力（`FileSystemPathIdentity`）和跨卷比较器，但全仓审计发现仍有 8 个文件在路径去重、快照保护、失败重试匹配和界面定位中残留硬编码的 `StringComparer.OrdinalIgnoreCase` 或 `OperatingSystem.IsLinux() / IsWindows()` 一刀切判断：
- `CompressionItemAdapter` 的输出备份目录恢复去重、失败残片快照 `SnapshotOutputFiles`、回滚保护集合与附件去重仍写死 `OrdinalIgnoreCase`；
- `DecompressionItemAdapter._processedArchives` 仍用 `OrdinalIgnoreCase`，会在区分大小写卷（Linux 或 macOS 区分大小写 APFS 外接卷）将 `pack.7z` 与 `Pack.7z` 误判为重复任务并跳过；
- `MainWindow.axaml.cs` 的 `PathsMatch` 写死仅 Windows 不区分大小写，macOS 默认 APFS 上略差大小写便无法高亮当前来源行，而 `BrowseAttachmentAsync` 又硬编码忽略大小写；
- `FailedItemRetryList`、`HeadlessBatchRunner`、`DiagnosticsExportService`、`ApplicationInfoService` 与 `BatchOperationService` 也各自写着基于 OS 的静态判断，无法兼顾 macOS 外接区分大小写卷与 Linux 挂载不区分大小写卷。
