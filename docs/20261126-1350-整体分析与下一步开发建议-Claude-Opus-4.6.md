## 2. 发现清单

### 2.1 【中】解压失败回滚：输出快照使用 `StringComparer.Ordinal`，macOS 大小写不敏感文件系统会误删已有文件

**文件**：`Core/Services/Pipeline/DecompressionItemAdapter.cs:309`

**现象**：`SnapshotOutputDirectory` 用 `StringComparer.Ordinal` 建立输出目录快照。macOS APFS 默认大小写不敏感：如果输出目录原有 `readme.txt`，而归档里有 `Readme.txt`（APFS 实际覆盖同一文件），解压失败回滚时 `Ordinal` 认为 `Readme.txt` 不在快照里，会删掉原有的 `readme.txt`。

**触发条件**：解压失败（密码错、CRC 坏块等）+ 输出目录有已有文件 + 归档内文件名与已有文件仅大小写不同。

**后果**：已有文件被误删。

**修复建议**：在 macOS 和 Windows 上使用 `StringComparer.OrdinalIgnoreCase`；Linux 保留 `Ordinal`。可用 `RuntimeInformation` 或 `OperatingSystem` 判断。

**置信度**：源码确认 + 逻辑推演；未实测（需构造大小写不同文件名的归档）。

### 2.2 【中】`IsAvailable()` 阻塞同步调用外部进程

**文件**：`Core/Services/SevenZipArchiveEngine.cs:233-235`、`Core/Services/RarArchiveEngine.cs:442`

**现象**：`TryValidateExecutable` 在 `FindExecutable()` 中被 `IsAvailable()` 调用，内部用 `.GetAwaiter().GetResult()` 同步等待外部进程（`7zz i`），超时 3 秒。

**触发条件**：首次界面启动时调用 `IsAvailable()`；若 7zz 路径指向不存在或挂起的程序，界面线程（构造函数中 `ArchiveEngineRouter` 间接调用）阻塞最多 3 秒。

**后果**：界面启动可能卡顿 3 秒。

**修复建议**：改为 `IsAvailableAsync` 异步方法，在启动时 `await`；或把校验推迟到首次真正执行时惰性完成。

**置信度**：源码确认。

### 2.3 【低】解压返回码 1 + 未开启后处理 = 完全算成功（退出码 0）

**文件**：`Core/Services/Pipeline/BatchExecutionPipeline.cs:421-432`

**现象**：解压时 7zz 返回码 1（有文件因密码或权限未解出），`ApplyPostProcess` 中如果用户未开启删除/移动（`Mode == None`），直接返回空列表——条目计入 `SuccessCount`，命令行退出码 0。

**这是既有已知行为**（README 和 `CompressionWarningPolicy` 注释已说明"解压返回码 1 仍计成功，只拦截删除/移动归档"）。如果用户希望调整，可以提供与压缩相同的"解压返回码 1 也算失败"策略（`DecompressionWarningPolicy`）。

**置信度**：源码确认 + 已知行为。

### 2.4 【低】`ArchiveResult` 是可变类而非不可变记录

**文件**：`Core/Models/OperationModels.cs` / 实际使用处

**现象**：`ArchiveResult` 有 `{ get; set; }` 属性，`CompressionWarningPolicy.Apply` 直接修改传入实例的 `Success` 和 `ErrorMessage`。如果未来有并发场景共享同一实例会不安全。目前串行/并发路径都是单实例使用，不构成当前缺陷，但属于设计债务。

**修复建议**：改为 `record` 或 `init` 属性，`Apply` 返回新实例。

**置信度**：源码确认。

## 3. 明确排除的误报

以下经源码核实不成立，列出以免后续重复分析：

1. **「解压返回码 1 会删除源归档」**——不成立。`ApplyPostProcess` 有 `HasWarnings` 拦截，实测损坏归档正确计为失败并保留归档。
2. **「7-Zip 从当前目录查找」**——已在 0.8.16 修复，`GetCandidatePaths` 不再包含当前目录。
3. **「诊断包泄露密码」**——已在 0.8.11+ 用 `CredentialRedactor` 脱敏（含引号整体、等号/冒号形式）。
4. **「运行日志明文密码是缺陷」**——用户已在 0.8.21 明确决定保留。
5. **「`批量压缩解压.csproj.user` 被跟踪」**——git ls-files 确认不在跟踪列表（已用 `git rm --cached` 清理过）。
6. **「进程取消不杀子进程树」**——`ArchiveProcessRunner.TryKill` 显式调用 `process.Kill(entireProcessTree: true)`。
7. **「覆盖模式会丢失旧归档」**——已在 0.8.15 改为备份改名+成功删除/失败恢复，测试覆盖。

## 5. 总结

0.8.22 的核心数据安全（返回码 1 拦截、覆盖备份恢复、残片回滚、后处理拦截）已经非常完善，110+43+155 项测试全绿，代码分层清晰。唯一发现的可能误删文件的场景是解压回滚时大小写不敏感文件系统的快照比较（概率低、影响范围限于解压失败路径），建议作为下一批优先修复。其余均为可维护性和体验改进。
