## 一、交付内容

### 1. 五份 JSON 资源

`Localization/Resources/{zh-CN,zh-TW,en,ja,de}.json`，每份 **294 个键**，结构：

```json
{
  "language": "zh-CN",
  "displayName": "简体中文",
  "strings": {
    "WindowTitle": "批量压缩解压工具",
    "...": "..."
  }
}
```

生成方式：临时写一个一次性导出测试，用反射把现有五套 `Create*()` 字典序列化出来，
人工核对后**删除该测试**（`grep` 确认源码无残留，只剩旧 `bin/obj` 二进制）。

### 2. 新增 `Localization/LocalizationLoader.cs`

- 从嵌入资源 `*.Resources.<语言>.json` 读取（按后缀匹配，不硬编码命名空间）。
- 属性映射只建一次，键名大小写不敏感；未知键写调试输出并忽略。
- **缺键保留 `LanguageStrings` 默认值**，不会变成空串；资源缺失或 JSON 损坏时
  整体回退默认值，保证程序能起来。

### 3. `LocalizationService` 收薄

- 五份 `Create*()` 全部删除：文件从 **1,757 行 → 107 行**。
- 构造函数与 `CurrentLanguage` setter 统一走 `LoadLanguage(language)`。
- `WithVersion` 改为幂等：先剥掉已有版本后缀，再拼当前运行版本。

### 4. 资源嵌入

- 主项目 `csproj` 加 `<EmbeddedResource Include="Localization\Resources\*.json" />`。
- 测试工程同步链接 `LocalizationLoader.cs` 并嵌入同一批 JSON，
  保证「测试里跑的就是交付的资源」，不是另写一份假数据。

## 二、实施中发现并处理的问题

**导出时窗口标题带上了测试程序集版本 `v1.0.0`。**
原 `Create*()` 里 `WindowTitle = WithVersion("批量压缩解压工具")`，
导出工具在测试程序集里运行，读到的是测试工程的 `1.0.0`。
若原样写进资源，正式应用标题会变成 `v1.0.0`。
处理：导出时剥掉版本后缀，资源只存基础标题；加载后由 `LocalizationService`
统一拼当前运行版本，`WithVersion` 改为幂等，避免重复拼接。
已加测试断言：资源里的 `WindowTitle` 不得包含 `v1.0.0`。

## 三、新增守护测试「本地化资源一致性」

| 断言 | 说明 |
| --- | --- |
| 五份 JSON 的键集合完全一致 | 防止漏翻译或键名拼错 |
| 键集合与 `LanguageStrings` 属性集合一致 | 防止反射赋值静默失效 |
| 每个值非空 | 防止界面出现空白文案 |
| 资源 `WindowTitle` 不含测试版本 | 防止版本污染 |
| 五种语言都能嵌入并被 `HasResource` 找到 | 防止资源漏打包 |
| 加载后五种标题都带运行版本且互不相同 | 防止语言切换不生效 |
| 测试结束恢复 zh-CN | 避免影响其它用例 |
