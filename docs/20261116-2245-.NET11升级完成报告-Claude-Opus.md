## 二、改了什么

### 2.1 SDK 与目标框架

- 用官方 `dotnet-install.sh` 把 **11.0.100** 安装到现有 `/Users/x/Tools/dotnet`，与 10.0.201/401/403 并排，不覆盖旧 SDK。
- `global.json` 固定 `11.0.100`，`rollForward: latestFeature` 保持不变。
- `BatchCompress.Avalonia.csproj` 与测试工程 `TargetFramework` 都改为 `net11.0`。
- `dotnet --version` 现在解析到 `11.0.100`；运行时 `Microsoft.NETCore.App 11.0.0` 已就位。

### 2.2 清理 NU1510 警告

.NET 11 把 `Microsoft.Extensions.Logging.Abstractions` 放进了共享框架；测试工程原来显式引用 `11.0.0`，构建时报：

```text
warning NU1510: PackageReference Microsoft.Extensions.Logging.Abstractions will not be pruned.
```

移除测试工程的显式包引用后，编译资产仍由主工程传递，测试构建恢复 0 警告。主工程的 `Microsoft.Extensions.Logging` / `Logging.Console` / `System.Resources.Extensions` 仍是 `11.0.0`，本次不升级依赖。

### 2.3 配套脚本与文档

- `测试夹具/经验验证/verify.sh` 里写死的 `bin/Debug/net10.0` 路径改为 `net11.0`（应用、测试程序集、应用日志目录三处）。
- GitHub 两个工作流的步骤名从“安装 .NET 10 SDK”改为“安装 .NET 11 SDK”；实际安装版本仍由 `global.json` 决定。
- README、`文档/ARCHITECTURE.md`、`文档/AVALONIA_VERSION.md`、`文档/测试方案.md`、`文档/详细设计文档.md`、`经验/07` 的当前版本表述同步为 .NET 11。
- 历史 `docs/` 与旧总结保持原文，不追改历史记录。

## 三、为什么能直接升

- Avalonia 12.1.6 的 NuGet 资产包含 `net10.0`/`net8.0`；`net11.0` 项目会选用 `net10.0` 资产，二进制兼容，实测全部测试与界面冒烟通过。
- 项目只使用稳定的 `ILogger` / `ILoggerProvider` 接口，没有依赖日志库内部类型；.NET 11 对日志库作者的变化不影响本项目的实现。
- 没有使用被 .NET 11 移除的 API；98 项测试覆盖命令行解析、归档命令构建、路径/分卷、诊断脱敏、管线进度、界面纯逻辑等，升级后无行为回退。
- 自包含单文件发布仍正常：macOS 打包后不依赖本机 .NET，状态栏帮助进程与最小压缩任务都通过。

## 四、升级时踩到的两个点

1. **测试工程硬编码 `net10.0` 路径**：`verify.sh` 的三处路径不改会读到旧 Debug 产物，出现“版本还是 0.8.13”的假失败。升级目标框架时必须同步所有脚本里的 TFM 路径。
2. **NU1510 不是错误但会破坏 0 警告基线**：.NET 11 共享框架自带 `Logging.Abstractions`，测试工程显式引用被判定为冗余。移除引用即可，不要用 `NoWarn` 掩盖。

## 六、回滚

回滚只需还原四处：

1. `global.json` 的 `version` 改回 `10.0.403`；
2. 两个 csproj 的 `TargetFramework` 改回 `net10.0`；
3. 测试工程恢复 `Microsoft.Extensions.Logging.Abstractions` 的显式引用（否则 net10 下编译资产可能需要）；
4. `verify.sh` 三处 `net11.0` 改回 `net10.0`。

回滚后重新构建即可，不涉及数据迁移或配置格式变化。
