# 批次 28 完成报告：三项决定落地（0.8.12）

> 用户原问题：**不要随包带 7-Zip 程序，没有的话自动从7z官网下载安装；命令行的自动关机开关要真的关机；图形界面与命令行的默认参数要统一**
> 完成时间：2026-11-16 20:45　版本：`0.8.11` → `0.8.12`　分支：`main`
> 性质：改产品源码，按约定版本号 +0.0.1

## 一、结论

三项决定全部落地，本机验证链全过。改动集中在三个新服务、两个入口的接线和一处界面状态默认值：

1. **Windows 不再随包带 7-Zip**：缺失时从 7-Zip 官方渠道自动下载并安装到当前用户目录，优先校验官方 SHA-256；不需要管理员权限，不写注册表（优先走 MSI 管理式解包）。
2. **命令行 `--shutdown` 真正关机**：与图形界面共用新的 `SystemPowerService`，Windows / Linux 保留一分钟延迟，macOS 改走 AppleScript（系统自带的 `shutdown` 需要 root，普通用户会直接失败）。
3. **两个入口默认参数统一**：压缩级别 3（标准）、恢复记录 3%、默认不分卷，唯一来源是 `ArchiveDefaults`；界面页签状态里那套旧默认值也一并改掉。

验证结果：**92 项单元测试、37 项经验实测、149 项端到端夹具、4 条界面冒烟、交付冒烟全过**；本机打包启动 `v0.8.12`，运行日志实测界面默认值为 `level=3, recovery=3%, volume=none`。

## 二、决定一：Windows 自动下载安装 7-Zip

### 2.1 原来的问题

Windows 发布配置没有任何复制 7-Zip 的条目，仓库里也没有 Windows 版二进制；代码里的第一个候选路径指向一个不存在的随包目录。用户没把 7-Zip 装到默认位置时，除 RAR 外的格式全部不可用，而报错只说「找不到命令行程序」。本机测试全在 macOS，覆盖不到这段。

### 2.2 实现

新增 `Core/Services/SevenZipProvisioner.cs`，职责单一：找到或准备好一份可用的 `7z.exe`。

- **固定安装位置**：`%LOCALAPPDATA%\BatchCompress\7zip`，当前用户可写，不需要管理员权限，不碰系统目录和系统环境变量。
- **查找顺序**：自动安装目录（要求 `7z.exe` 与 `7z.dll` 同时存在）→ 旧版随包目录（仅兼容开发机残留）→ `Program Files\7-Zip` → `Program Files (x86)\7-Zip` → `%LOCALAPPDATA%\Programs\7-Zip`。
- **下载来源**：优先请求 7-Zip 官方 GitHub 发布接口 `api.github.com/repos/ip7z/7zip/releases/latest`，从中取 64 位 MSI / EXE 的下载地址、文件大小与 `digest` 里的 SHA-256。接口不可用时退回官方下载页 `www.7-zip.org/download.html` 解析链接，此时没有官方校验值，日志会明确写「仅依赖 HTTPS」。
- **安装方式**：先尝试 MSI 管理式解包（`msiexec /a ... /qn TARGETDIR=...`，只展开文件、不注册组件），失败再退回 EXE 静默安装（`/S /D=...`）。两条路都不请求管理员权限。
- **归位**：解包后递归找到 `7z.exe`，把 `7z.exe`、`7z.dll`、许可与说明文件复制到安装根目录。缺 `7z.dll` 判定为安装失败——WIM 等格式依赖它，不能在真正跑任务时才暴露。
- **安装后校验**：执行一次 `7z.exe i`，返回码属于成功范围且输出包含 `7-Zip` 才算成功，避免把损坏下载当成可用程序。
- **安全边界**：下载上限 64 MB；SHA-256 不匹配直接拒绝；所有子进程参数用参数列表逐个传递，不拼 Shell 字符串；临时文件在 `finally` 清理。

### 2.3 两个入口的触发时机

| 入口 | 触发点 | 行为 |
| --- | --- | --- |
| 图形界面 | 主窗口 `Loaded` 后后台检查；点击「压缩」「解压」前再确保一次 | 不阻塞窗口出现；同一进程只尝试一次，结果写入命令日志并弹通知 |
| 命令行 | 参数校验与试运行判断之后、归档引擎可用性检查之前 | 下载进度写标准错误，不污染结构化输出；失败只告警，不中断 RAR 任务 |

`SevenZipArchiveEngine` 的 Windows 候选路径改为优先读自动安装目录，并补上 32 位 Program Files 与用户级安装位置。

### 2.4 失败时用户看到什么

归档引擎的「找不到程序」提示在 Windows 上改为：说明自动下载安装也未成功，请联网重试，或从 `https://www.7-zip.org/download.html` 手动安装。命令行会额外打印具体失败原因（网络、校验、解包或身份校验）。

### 2.5 未验证项

本机是 macOS，**没有 Windows 机器可实测**。已验证的是纯逻辑部分：官方发布 JSON 解析、下载页解析、安装布局归位、SHA-256 计算；「MSI 解包 / EXE 静默安装是否在真实 Windows 上成功」属于待实机确认项，不能因为单元测试通过就当成已跑通。

## 三、决定二：命令行 `--shutdown` 真正关机

### 3.1 原来的问题

命令行注入的系统集成实现只写一行日志和一句 `System shutdown requested.`，不执行任何系统命令；五份帮助却都承诺「全部完成后请求关机」。这是「说了会做、静默没做」。

### 3.2 实现

新增 `Core/Services/SystemPowerService.cs`，不依赖界面框架，命令行与图形界面共用：

| 平台 | 关机命令 | 取消命令 | 说明 |
| --- | --- | --- | --- |
| Windows | `shutdown /s /t 60` | `shutdown /a` | 保留一分钟延迟与取消能力 |
| Linux | `shutdown -h +1` | `shutdown -c` | 通过系统关机命令提交，权限不足会返回失败 |
| macOS | `osascript -e "delay 60" -e "tell application \"System Events\" to shut down"` | 结束待执行的 AppleScript 进程 | `/sbin/shutdown` 需要 root；AppleScript 以当前用户身份请求，延迟放在脚本自身，保留取消窗口 |

`SystemIntegrationService`（界面）改为委托该服务；`HeadlessBatchRunner` 内部的命令行实现也改为真正调用，并把「已提交 / 失败」写进日志、失败走标准错误。

macOS 侧还有一个必要改动：在 `macos/Info.plist` 增加 `NSAppleEventsUsageDescription`（说明「执行完成后关机功能时需要请求系统关机」）。没有这条说明，系统无法就自动化控制弹出授权提示，AppleScript 会被拒绝。

### 3.3 未实测说明

**没有在本机执行真实关机**，否则会直接关掉开发机。验证方式是单元测试检查三种平台的命令与参数构造，并检查命令行实现确实调用了关机服务；真实关机行为需要在你方便时、且能接受机器关闭的条件下自行验证一次。macOS 首次使用会弹一次自动化授权，需要允许。

## 四、决定三：默认参数统一

### 4.1 统一后的取值

| 参数 | 命令行（原来） | 图形界面（原来） | 统一后 |
| --- | --- | --- | --- |
| 压缩级别 | 3（标准） | 1（最快） | **3（标准）** |
| 恢复记录 | 3% | 0（关闭） | **3%** |
| 分卷 | 默认不分卷 | 默认开启、20 GB 一卷 | **默认不分卷** |

选择这组值的理由：标准压缩是更中性的默认；3% 恢复记录在体积增加很小的情况下提升可恢复性；默认不分卷避免用户意外得到一堆分卷文件。命令行原本就是这组值，因此行为变化只发生在图形界面。

### 4.2 唯一来源与一个容易漏的坑

在 `Core/Models/ArchiveDefaults.cs` 增加四个常量：`DefaultCompressionLevel = 3`、`DefaultRecoveryRecordPercent = 3`、`DefaultEnableVolume = false`、`DefaultVolumeSize = "20"`、`DefaultVolumeUnit = "g"`。

- 命令行选项初值改读常量；
- 界面的压缩级别、分卷开关、恢复记录、分卷大小字段初值改读常量；
- **界面的页签状态类 `OperationTabState` 里还有一套旧默认值**（最快、开分卷、恢复记录 0）。切换页签时它会覆盖字段初值，如果只改字段初值，用户一切到解压页就会看到旧默认。这次一并改成常量，并加了源码守护测试。
- 界面启动时把实际默认值写进运行日志（`GUI_DEFAULTS`），方便以后核对两个入口是否仍然一致。

### 4.3 运行时证据

本机启动 `v0.8.12` 后，最新界面日志第 2 行：

```text
[INFORMATION] [GUI_DEFAULTS] level=3, recovery=3%, volume=none
```

命令行实测同样输出：

```text
[DEFAULTS] level=3, recovery=3%, volume=none
```

显式传参仍可覆盖：`--level 5 --recovery 7 --volume-size 10 --volume-unit m` 的日志为 `level=5, recovery=7%, volume=10m`。

## 七、风险与回滚

- **Windows 自动安装未实机验证**：最可能出问题的是 MSI 管理式解包在某些系统策略下被拒绝；已保留 EXE 静默安装作为后备，并在两条路都失败时给出可操作的手动安装提示。
- **网络与代理**：企业网络可能拦截 GitHub 或 7-zip.org；失败只影响 7-Zip 格式，不会中断 RAR 任务，提示里带手动下载地址。
- **macOS 自动化授权**：首次关机需要允许一次；若拒绝，AppleScript 无法控制系统关机，日志会记录失败。
- **默认值变化**：图形界面用户升级后会看到「标准压缩、3% 恢复记录、不分卷」。这是用户明确要求的统一，已写进 README 与版本说明；老用户此前在页签里改过的值仍会在本次运行中保留（内存状态），下次启动回到统一默认。
- **回滚**：本批是单个提交，可整体 `git revert`。自动安装目录是普通文件夹，删除 `%LOCALAPPDATA%\BatchCompress\7zip` 即可清理，不会留下注册表项（优先 MSI 解包路径）。
