# v0.8.18 批次安全与命令行收尾

> 更新时间：2026-11-20 15:53（中国标准时间）　版本：`0.8.18`　分支：`main`

## 本轮结果

本轮把压缩批次的输出检查收敛到 `BatchPreflightService`，图形界面、命令行界面（CLI）与试运行（dry-run）共用同一套无副作用预检。批次遇到以下情况时会在创建输出目录、启动压缩引擎和执行源文件后处理之前整体停止：

- 多个来源计划生成同一路径，或分卷逻辑主文件名相同；
- 目标归档路径与本批次任一来源路径相同；
- 输出目录位于一个待压缩目录内部。

目录批量选择时，集合根目录下恰好等于输出目录的直接子项会从来源中排除。判断同时比较字面路径和解析后的符号链接路径，覆盖输出目录自身为符号链接的情况；若输出目录藏在另一个待压缩子目录中，则保留该来源并阻止批次。

来源路径按字面值去重，保留 Linux（Linux 操作系统）上大小写不同的合法来源。目标冲突比较目前依照操作系统默认卷行为：Windows（微软桌面系统）与 macOS（苹果桌面系统）忽略大小写，Linux 区分大小写。批次并发预处理的进度回调现在各自接收快照，避免异步派发时显示成最后一个来源的消息。

Windows 命令行程序启动时会尝试连接父控制台并重开标准输入、输出和错误流；无参数以及仅有语言参数的图形界面启动不会附加控制台。当前在 macOS 上验证了分类逻辑与跨平台构建，未在 Windows 真机验证控制台连接和输出重定向。

## 风险与边界

- macOS 的大小写敏感 APFS 卷、Windows 目录级大小写敏感模式可能与系统默认假设不同。当前比较会倾向于多拦截，不会因此静默丢弃来源。后续可按具体卷/目录能力做更精确判断。
- Windows 控制台附加与管道重定向仍需 Windows 真机验证；Windows/Linux 真机测试依照既有项目决定暂停。
- 本轮没有改变 RAR（归档格式）分发、日志明文保留、GitHub Actions（自动化工作流）历史文件的既有决定。
- 版本脚本 `~/.codex/skills/pixian-dev-workflow/scripts/bump_version.py` 把 `0.8.17` 自动进位成了 `0.9.0`，与项目补丁号连续递增不符。本轮通过同一脚本的 `--set 0.8.18` 固定正确版本；未擅自修改用户级脚本。
