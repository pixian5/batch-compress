## 二、三个真实缺陷

### 2.1 崩溃日志被常规日志挤出诊断包（高）

`DiagnosticsExportService.ExportAsync` 原来把三类目录里的日志混在一起，
按最后写入时间倒序 `Take(10)`。界面运行日志（`batchcompress_gui_*.log`）通常比崩溃日志新，
一旦常规日志达到 10 份，`batchcompress-crash_*.log` 就一份都进不了包。
而崩溃日志带版本、运行时、完整堆栈，恰恰是排障时最需要的那一份。

**复现测试**：`Program.AboutInfoTests.cs` 的 `TestDiagnosticsKeepsCrashLogsWhenRegularLogsAreMany`
造 1 份一小时前的崩溃日志 + 12 份较新的常规日志，断言包内仍有崩溃日志且总数 ≤ 10。
修复前 FAIL。

**修法**：先按文件名筛出崩溃日志，按时间取最近的 `MaxCrashLogs = 3` 份并锁定名额，
剩余 `10 - 已占名额` 个位置再由其它日志按时间倒序补足；用 `HashSet<string>` 去重避免重复入选。

```csharp
var crashLogs = allLogs
    .Where(path => Path.GetFileName(path)
        .StartsWith("batchcompress-crash_", StringComparison.OrdinalIgnoreCase))
    .OrderByDescending(File.GetLastWriteTimeUtc)
    .Take(MaxCrashLogs)
    .ToList();
var selectedCrash = new HashSet<string>(crashLogs, pathComparer);
var regularLogs = allLogs
    .Where(path => !selectedCrash.Contains(path))
    .OrderByDescending(File.GetLastWriteTimeUtc)
    .Take(MaxLogFiles - crashLogs.Count);
var recentLogs = crashLogs.Concat(regularLogs).ToList();
```

### 2.2 等号/冒号形式的密码明文进入诊断包（高）

`RedactSensitiveText` 原来只处理 `--password "xxx"`、`--password xxx`、`-pxxx`、`-hpxxx`。
结果报告服务 `BatchReportService` 的注释与正则早已把 `--password=xxx` / `--password:xxx`
列为真实命令里会出现的形式，两处规则不一致。诊断包是设计为可对外分享的，
这类写法会把明文口令原样带出。

**复现测试**：`TestDiagnosticsRedactsPasswordAssignmentForms` 造含
`--password=`、`--password:`、`--password="..."`、`-hp=`、`-p=` 五种写法的日志，
断言导出文本里不再出现明文口令。修复前 FAIL。

**修法**：新增一条合并规则，带引号与不带引号一次替换，避免二次替换把占位符再改一遍。
规则识别 `--password` 后紧跟等号或冒号的情况，其后无论是带引号的值还是连续非空白字符，
整体替换为固定的脱敏占位符：

```csharp
// 等号/冒号赋值形式，含带引号变体，一次替换到位
result = Regex.Replace(result, @"(--password)[=:](?:""[^""]*""|\S+)", "$1=***");
```

等价于「`--password` 后紧跟等号或冒号，其后无论带引号的值还是连续非空白字符，
整体换成固定的脱敏占位符」。

`-p=xxx` 与 `-hp=xxx` 经核查已被原有 `\S+` 规则吃掉（输出 `-p***` / `-hp***`），
因此没有新增同类规则，避免改变现有测试断言的脱敏格式。

### 2.3 「关于」弹窗长字段名溢出到数值列（中）

`Views/AboutWindow.axaml` 的标签列固定 180 像素，样式里只设了字重、边距与对齐，
**没有开启换行**。德语 `Standardverzeichnis für Ergebnisberichte`、
`Absturzprotokollverzeichnis`、日语与英语的部分字段名都会超出列宽，
与右侧路径文字重叠。上一轮只做了中文截图核对，没覆盖长文案语言。

**修法**：给 `TextBlock.aboutLabel` 样式加 `<Setter Property="TextWrapping" Value="Wrap"/>`。

**实测核对**：用一次性验收钩子（环境变量指定语言、挂主窗口 `Opened` 事件）把界面切到德语，
系统截图确认六个标签全部折行完整显示、数值列路径换行可读、
`Protokollverzeichnis öffnen` / `Diagnose exportieren` / `Schließen` 三个按钮齐全、
底部说明完整。钩子与截图核对后已删除并清理，撤钩后重新构建、打包、重跑冒烟。

## 三、复查中排除的疑点

- **担心界面日志被纳入诊断包后，会把「密码查询」功能的明文密码带出去**：
  核查 `MainWindowViewModel.Logging.cs` 与 `OperationSession.cs` 确认，界面命令日志
  （含密码查询候选与最终密码）只写进内存中的 `CommandLog` 供界面显示，
  **不写入 `FileLoggerService` 的磁盘日志**；诊断包扫描的是磁盘文件，这条路径不存在。
- **担心单目录构造入口与新增多目录入口传 `null` 时编译歧义**：
  全部调用点都是具体值（字符串或数组），当前代码无裸 `null` 调用；旧入口保留不动，
  不影响回滚。记为潜在卫生项，不在本轮扩大改动。
- **担心路径口径还有遗漏**：全仓库扫描确认 `AppContext.BaseDirectory/logs`、
  `ApplicationData`、`DesktopDirectory`、`GetTempPath()` 的拼写只出现在
  `ApplicationInfoService`、`CrashLogService`、`WindowStateService`（窗口设置，属另一类路径）、
  `EnclosureConfigService`（附件配置，属另一类路径）与测试代码中，日志/报告/诊断三类已收口。
