## 一、交付内容

### 1. 新增 `ViewModels/LogBuffer.cs`

- `Append`：按 `\r\n` / `\n` / `\r` 三种换行拆行入队；超出上限丢最旧并累计省略数；
  空文本与 null 直接忽略。
- `TryFlush`：按 `Environment.TickCount64` 判断是否到 200 毫秒，未到返回 false 并保留待刷新标记；
  **不引入定时器**，避免额外生命周期管理。
- `Flush`：无条件输出完整文本（批次结束、清空、导出前使用）。
- `Clear`：内容、省略计数、节流状态一起归零。
- 文本开头在有省略时插入「（已省略最早的 N 行）」。

### 2. 新增 `ViewModels/MainWindowViewModel.Logging.cs`

- 三个缓冲：命令日志、成功日志、失败日志，参数统一为 5,000 行 / 200 毫秒。
- `AppendCommandLog` / `AppendSuccessLog` / `AppendFailLog` 三个统一入口，
  只在 `TryFlush` 返回 true 时更新绑定属性。
- `ForceFlushLogs()`：批次结束、导出前强制刷新。
- `ResetCommandLog` / `ResetSuccessLog` / `ResetFailLog`：清空缓冲并把属性置空。

### 3. 替换全部日志追加点

- `CommandLog +=` 31 处、`SuccessLog +=` / `FailLog +=` 各 1 处，全部改为统一入口。
- 跨多行的 `string.Format(...) + "\n" + string.Join(...)` 整体作为参数，
  保持原有换行与内容顺序。
- `grep "CommandLog +="` 结果为 0。
- **没有动** `SourceFileList`：它是源清单而不是日志，由选择/导入逻辑整体赋值。

### 4. 清空与刷新时机

- 三个 `ClearXxxLog` 命令改为「清缓冲 + 置空属性」——只置空属性的话，
  下一次刷新会把旧内容带回来。
- `OperationSession.RunAsync` 的 `finally` 里调用 `ForceFlushLogs()`，
  保证节流窗口内的最后几行不会延迟到下一次刷新才出现。

### 5. 报告收集器上限

- `BatchReportCollector.MaxEntries = 20_000`；超出后只累计 `OmittedEntries`，
  不再加入明细，计数快照照常推进。
- `ToCsv` / `ToMarkdown` / `Write` 增加可选 `omittedEntries` 参数；
  有省略时 CSV 追加一行「另有 N 条因超出上限未列出」的说明（保持 7 列结构），
  Markdown 追加引用行。
- 命令行 `--report` 与界面「导出本次结果」都传入实际省略数。

## 四、说明与限制

- 节流参数是「按时间判断」而不是固定定时器：如果一批任务在 200 毫秒内结束，
  期间可能一次都不刷新，但 `finally` 的强制刷新会把最终内容补上。
- 容量只控制行数，**不改变内容**：命令日志仍保留含密码的原始输出，
  这是既定诊断行为，不在本批次范围内。
- 10 万行量级验证在单元测试内完成；真实界面的滚动流畅度仍建议在大批量任务时人工观察一次。
