## 二、P4-3　多任务历史导出与审计报告

- **现状**：界面有源列表 / 成功 / 失败 / 命令日志四类记录，但只能在窗口里看；
  批次 16 的 `DiagnosticsExportService` 是「脱敏打包日志」，用途不同，不能直接复用输出内容。
- **目标**：把本次批处理的逐项执行清单导出为 CSV（逗号分隔值）或 Markdown 汇总表，
  便于留档与复盘。
- **改动点**：
  1. 在会话 / 进度模型里累积逐项结果（来源、成功或失败、失败原因、耗时、字节数、分卷数）；
  2. 新建 `BatchReportService`，只从结构化字段生成报告，**不读取命令日志文本**；
  3. 界面加「导出本次结果」按钮与五语言词条；CLI 可提供 `--report <path>`；
  4. 明确声明：报告默认**不含密码、不含原始命令行**。
- **验收**：导出文件行列与任务数一致；失败项带原因；用含密码的批次跑一遍，
  报告中搜不到明文密码；73 项测试 + 19 项实测 + 149 项夹具不回归。
- **风险**：最容易出错的是「顺手把命令日志拼进报告」导致密码外泄，
  代码评审时要专门检查数据来源只能是结构化字段。
- **版本**：改产品源码，`+0.0.1`。

## 四、需要你拍板的两件事（仍无决定）

**1. macOS 正式签名与公证。**
现状：`package-macos.sh` 支持注入证书做硬化运行时签名，无证书时是临时签名；
0.8.3 的应用已在本机启动运行，但脚本每次都会打印 Gatekeeper（系统门禁）绕过指引。
不改的后果：别人从发布页下载会被系统拦截，macOS 分发只对开发者可用。
选项：① 接入 Apple Developer 账号（年费）＋开发者证书＋公证；
② 维持临时签名并在发布说明写清绕过方法；③ 暂不分发 macOS 包。
**推荐 ①**：流水线已齐，只差证书与公证步骤。

**2. RAR 随 Linux 产物分发。**
现状：`--no-rar` 纯净版已可构建，完整版仍随 `linux-x64` 产物发布。
选项：① 做许可复核并把结论写进风险文档；② 纯净版设为默认、完整版可选；
③ 完全不随产物分发 RAR。**推荐 ②**。
