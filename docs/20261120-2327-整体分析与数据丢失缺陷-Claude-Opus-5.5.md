# 整体分析与数据丢失缺陷（0.8.19，只读）

> 时间：2026-11-20 23:27　版本：`0.8.19`　模型：Claude Opus 5.5
> 本轮只做分析与实测，不改产品源码，因此沿用项目惯例不递增版本号。

## 1. 项目现状

- 技术栈：.NET 11（SDK `11.0.100`）+ Avalonia 12.1.6 + CommunityToolkit.Mvvm；压缩解压通过外部 7-Zip（`7zz`）与 RAR/WinRAR 命令行完成。
- 入口：图形界面（`Views/`、`ViewModels/`）与命令行（`CommandLineHandler.cs`、`HeadlessBatchRunner.cs`）共用 `Core/Services/Pipeline` 执行管线。
- 规模：受跟踪文件 480 个，C#/AXAML 约 2.3 万行（不含 `old/`），提交 303 次。
- 本轮基线：Release 构建 0 警告 0 错误；测试控制台 109 项全部通过。
- 外部进程参数全部通过 `ArgumentList` 逐项传入，路径都先经 `Path.GetFullPath` 变成绝对路径，因此文件名以 `-` 开头不会被 7zz 当成开关。

## 2. 高优先级：返回码 1 被当成功，触发删除源导致数据丢失

### 位置

- `Core/Services/SevenZipCommandBuilder.cs:152`：`SevenZipExitCodes.IsSuccess` 把 `0` 和 `1` 都算成功。
- `Core/Services/WinRarCommandBuilder.cs:138`：`WinRarExitCodes.IsSuccess` 同样处理。
- `Core/Services/Pipeline/BatchExecutionPipeline.cs:126-139`（串行）与 `:323` 附近（并发）：`result.Success` 为真就执行删除/移动后处理。

7-Zip 文档中返回码 1 的含义是“非致命警告，例如有文件被占用而没有压进去”。RAR 的返回码 1 含义相同。

### 实测复现（macOS，本仓库自带 `tools/7zip/macos/7zz`）

```bash
mkdir -p src/data out
echo a > src/data/ok.txt
echo important > src/data/locked.txt
chmod 000 src/data/locked.txt
dotnet run -c Release --no-build -- --compress --source src/data --output out \
  --format 7z --test --delete-source
```

结果：

- 命令行汇总 `Success=2, Failed=0`，退出码 0。
- 7zz 输出 `WARNING: Cannot open 1 file`，返回码 1。
- `out/locked.txt.7z` 仅 158 字节，里面没有任何文件；`7zz t` 校验仍然报 `Everything is Ok`，所以 `--test` 拦不住。
- `src/data/locked.txt` 已被删除，内容无法找回。

如果来源是整个目录、其中只有部分文件不可读，整个目录会在归档不完整的情况下被递归删除。移动模式不会丢数据，但会把未完整归档的来源移进“已处理”目录，同样误导用户。

### 修复建议（待用户决定）

1. 返回码 1 不再等同于成功：引擎结果区分“成功”“成功但有警告”，管线在“有警告”时计入失败或单独的警告计数，并且**禁止执行删除/移动后处理**。
2. 最保守的做法：压缩只把返回码 0 当成功；解压的返回码 1 按同样规则处理。
3. 补回归测试：不可读文件（`chmod 000`）+ `--delete-source`，断言源文件保留、条目计为失败或警告、退出码非 0。

## 3. 中优先级：运行日志写入明文密码

- 实测命令 `--password 'MySecret123'` 后，运行日志 `bin/Release/net11.0/logs/batchcompress_*.log` 第 19 行记录了完整 7zz 命令行 `-pMySecret123`。
- 文件名密码模式同样记录 `-p<派生密码>`。
- `CredentialRedactor` 只在导出诊断包、结果报告和 NDJSON 时脱敏，写日志时没有调用。日志文件权限为 0600，风险限于本机，但用户把日志直接发给别人排查问题时会泄露密码。
- 建议：在记录命令行的位置统一调用 `CredentialRedactor`，让磁盘日志与诊断包使用同一套规则。

另一个无法完全消除的点：密码作为 `-p` 参数传给 7zz，本机其他进程可以通过 `ps` 看到。7zz 没有从标准输入或文件读密码的非交互开关，这一点只能在文档里说明。

## 4. 低优先级与仓库卫生

- `批量压缩解压.csproj.user` 被 Git 跟踪，而 `.gitignore` 已忽略 `*.user`，属于历史遗留，可用 `git rm --cached` 移除。
- 本地 `bin/` 占 2.5 GB（已被忽略，不进仓库），可以定期清理。
- `tools/` 下的 7zz 与 Linux RAR 二进制约 13 MB 进入仓库，是既有决定，这里只记录。

## 5. 建议执行顺序

1. 修复返回码 1 的处理和后处理拦截，补回归测试（版本 `0.8.20`）。
2. 磁盘日志接入 `CredentialRedactor`，补“日志不含密码”测试。
3. 清理被跟踪的 `.csproj.user`。
