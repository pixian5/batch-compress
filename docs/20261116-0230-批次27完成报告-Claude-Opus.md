## 一、结论

「关于」弹窗按设计落地，并且顺带修掉了一个此前没被任何测试覆盖的真实缺陷：
**「导出诊断」几乎收不到日志**——界面运行日志写在用户数据目录，崩溃日志文件名前缀与导出过滤不匹配，
而导出只扫描应用目录里的一个 `logs` 文件夹。修复后，诊断包会同时收集界面日志、崩溃日志与命令行日志。

本机全量验证全过：85 项单元测试、29 项经验实测、149 项端到端夹具、4 条界面冒烟、交付冒烟、
macOS 打包启动与窗口标题核对。应用当前运行版本为 `v0.8.10`。

## 二、排查中发现的真实缺陷

设计方案第 7 节要求弹窗显示「日志目录、崩溃日志目录、结果报告目录」。核对实际写入路径时发现，
这三类路径此前分散在四处各自拼接，而且彼此对不上：

| 用途 | 修复前的实际位置 | 问题 |
| --- | --- | --- |
| 界面运行日志 | `Environment.SpecialFolder.ApplicationData/BatchCompress.Avalonia/logs`，文件名 `batchcompress_gui_*.log` | 与诊断导出的扫描目录完全无关 |
| 崩溃日志 | `CrashLogService.LogDirectory` = `AppContext.BaseDirectory/logs`，文件名 `batchcompress-crash_*.log` | 文件名前缀不匹配导出过滤 |
| 诊断导出过滤 | `Directory.EnumerateFiles(dir, "batchcompress_*.log*")`，再加正则 `\.log(\.\d+)?(\.gz)?$` | `batchcompress-crash_*` 用的是连字符，永远不匹配 |
| 诊断导出扫描范围 | 界面侧写死 `Path.Combine(AppContext.BaseDirectory, "logs")`；命令行侧用 `--log-file` 所在目录 | 界面侧的 GUI 日志一份也扫不到 |
| 结果报告默认目录 | 界面导出命令里各自写「桌面，不存在则临时目录」 | 没有可复用的单一口径 |

**直接后果**：从图形界面点「导出诊断」，生成的 zip 里通常只有 `diagnostics_summary.json`；
界面运行日志与崩溃日志都不会进入包内，排障时拿不到关键线索。此前 149 项夹具和 81 项测试都没有覆盖
「跨目录 + 崩溃日志文件名」这一组合，所以一直没暴露。

## 三、实现清单

### 3.1 新增 `Core/Services/ApplicationInfoService.cs`

纯 .NET、不引用任何 Avalonia 类型，因此可以直接链接进测试工程。对外提供：

```csharp
public sealed record ApplicationInfo(
    string Version, string Runtime, string OperatingSystem,
    string GuiLogDirectory, string CrashLogDirectory, string ReportDirectory,
    IReadOnlyList<string> DiagnosticsLogDirectories);

public static class ApplicationInfoService
{
    public static string ReadApplicationVersion();          // 与 --version 同源
    public static string ResolveGuiLogDirectory();          // 界面运行日志目录
    public static string ResolveCliLogDirectory();          // 命令行默认日志目录
    public static string ResolveReportDirectory();          // 桌面，不可用则临时目录
    public static IReadOnlyList<string> ResolveDiagnosticsLogDirectories();
    public static ApplicationInfo Create();
}
```

关键约定：

- `ReadApplicationVersion()` 读取 `AssemblyInformationalVersionAttribute` 并去掉 `+` 之后的元数据，
  与 `Program.cs` 中 `--version` 的写法完全一致，避免弹窗与命令行显示两个版本。
- `ResolveDiagnosticsLogDirectories()` 返回「界面日志目录 + `CrashLogService.LogDirectory` + 命令行日志目录」
  去重后的并集。后两者默认同路径，正常情况是 2 个目录。
- 去重比较器在 Linux 用 `Ordinal`（大小写敏感），其它平台用 `OrdinalIgnoreCase`。
- `OperatingSystem` 显示 `RuntimeInformation.OSDescription` 加 `OSArchitecture`；
  `Runtime` 显示 `RuntimeInformation.FrameworkDescription`。

### 4.1 弹窗真实渲染核对

Avalonia 在 macOS 的辅助功能树只暴露窗口标题与三个匿名按钮，无法靠点击自动化按钮。
因此用一次性验收钩子（环境变量触发、挂在主窗口 `Opened` 事件上）把弹窗真实弹出来，
再用系统截图核对。实测显示：

| 字段 | 实际显示值 |
| --- | --- |
| 版本 | `0.8.10` |
| .NET 运行时 | `.NET 10.0.14` |
| 操作系统 | `macOS 27.2.1 (Arm64)` |
| 运行日志目录 | `/Users/x/Library/Application Support/BatchCompress.Avalonia/logs` |
| 崩溃日志目录 | `/Users/x/code/compress/bin/Debug/net10.0/logs`（调试运行；打包后在 `.app` 内） |
| 结果报告默认目录 | `/Users/x/Desktop` |

底部三个按钮「打开日志目录」「导出诊断」「关闭」齐全，长路径自动换行，说明文字完整，
没有截断、重叠或空白区域。**钩子在核对后已删除，截图已清理，随后重新构建、重新打包、重跑冒烟**，
确认交付产物不含任何验收代码。

### 4.2 过程中两个失败与处理

- 经验实测第 18 节第一次跑出 1 项 FAIL。排查确认导出逻辑正确（手工复现时两个日志都在包内），
  失败原因是脚本里 `unzip -Z1 | grep -q` 在 `pipefail` 下会因 `grep -q` 提前关闭管道，
  把 `unzip` 的 SIGPIPE 当成失败。改为先取整份清单到变量、再用 zsh 字符串匹配判断，29 项全过。
- 一次性验收钩子最初在 `OnFrameworkInitializationCompleted` 里直接 `Show(_mainWindow)`，
  Avalonia 报 `Cannot show window with non-visible owner`（主窗口尚未显示）。
  改为挂到主窗口 `Opened` 事件后正常弹出。

## 五、与设计文档的偏差（如实记录）

| 设计文档写法 | 实际做法 | 原因 |
| --- | --- | --- |
| 「五语言 5 个词条」 | 实际 12 个 | 六个字段名、标题与悬停提示、两个按钮加关闭、失败提示、路径说明都需要翻译；估少了 |
| 「结果报告目录」 | 显示「结果报告默认目录」，并附命令行覆盖说明 | 没有单一固定目录：命令行由 `--report` 指定，界面默认桌面（不可用时临时目录） |
| 「ViewModel 增加只读属性与命令」 | 复用主窗口 ViewModel 的分部文件，不新建 ViewModel 类 | 弹窗与主窗口共用 DataContext，语言切换与已有命令天然复用 |
| 「版本 +0.0.1」 | `0.8.9 → 0.8.10` | 按项目版本约定执行 |
| 未明确入口位置 | 只加主界面「开始」页按钮，不加托盘菜单 | macOS 托盘由独立的原生状态栏帮助进程绘制，菜单结构不同，强行加会导致三平台行为不一致 |
