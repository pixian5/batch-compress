## 一、当前状态

按用户「继续」完成设计方案第 7 节剩下的完整功能项——**「关于」弹窗**（记为批次 27），
版本 `0.8.9 → 0.8.10`（修改产品源码，按约定 `+0.0.1`）。

实施过程中发现并修掉一个真实缺陷：此前「导出诊断」只扫描应用目录里的 `logs`，且只认
`batchcompress_*.log*` 前缀，导致**界面运行日志与崩溃日志都进不了诊断包**。
现在版本、运行时、操作系统与四类产物路径统一由 `Core/Services/ApplicationInfoService.cs` 计算，
写入方、展示方、收集方复用同一口径，诊断包可同时收集界面日志、崩溃日志与命令行日志。

**项目定位不变**：本地应用，交付与验证全部在本机完成，不依赖云端持续集成；按用户决定，
macOS 正式签名与公证、RAR 随 Linux 产物分发的许可结论、云端 Actions 三类事项均不再处理，也不再列为待办。

## 五、遗留风险

- 仅在 macOS（Apple Silicon）实机验证；Windows 10 与 Debian 13 未实机跑过。按项目定位，本机验证即交付依据。
- 「关于」里的崩溃日志目录在调试运行时指向 `bin/Debug/net10.0/logs`，打包运行指向 `.app` 内部路径；
  两者都是当时的真实落点，不是错误，但排查时要留意当前跑的是哪份产物。
- Avalonia 在 macOS 的辅助功能树只暴露窗口标题与三个匿名按钮，界面按钮点击无法稳定自动化；
  本批用一次性钩子 + 截图做了单次人工核对，未加入长期冒烟脚本。
