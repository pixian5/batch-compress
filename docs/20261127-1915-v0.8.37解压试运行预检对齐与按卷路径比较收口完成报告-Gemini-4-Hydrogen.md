# v0.8.37 解压试运行预检对齐与按卷路径比较收口完成报告

> 用户原问题：继续
> 关联基准：`v0.8.36`（提交 `1caf471`） -> `v0.8.37`

## 1. 背景与发现

在完成 `v0.8.36` 工程结构治理后的全仓静态审计中，发现了几处真实存在的行为缺口与平台差异隐患：
1. **命令行 `extract --dry-run` 预检盲区**：`HeadlessBatchRunner.RunDryRun()` 此前仅在压缩模式调用预检；遇到缺失分卷（如缺首卷 `.001` 或缺失中间卷 `.002`）、重复分卷编号或大小写歧义时，解压试运行不仅不报错还会错误返回退出码 `0`，与实际解压失败口径及 GUI 预检不一致；同时 `GuiPreflightService` 与 `DecompressionItemAdapter` 各自维护了一套几乎相同的分卷校验逻辑。
2. **遗留静态路径比较器**：`ArchiveVolumeResolver.ResolveOutputFiles` 仍硬编码 `StringComparer.OrdinalIgnoreCase`（在 `Case-sensitive APFS` / `ext4` 上会把仅大小写不同的输出分卷折叠去重）；`BatchOperationService` 中的密码本去重/预检源汇总、`CliCommandBuilder` 的临时目录比较以及 `RarArchiveEngine.IsUnderBaseDirectory` 仍混用静态 `Ordinal` 或 `OrdinalIgnoreCase`。
3. **界面提示补齐**：主窗口“添加附件”复选框（`AddAttachments`）与“关于”弹窗“导出诊断”按钮（`ExportDiagnostics`）尚缺少 `ToolTip.Tip` 绑定（对应本地化词条 `TooltipAttachmentList` 与 `TooltipExportDiagnostics` 在五语言资源中早已就绪）。

## 2. 核心改动清单

### 2.1 统一解压路径预检器与 CLI `extract --dry-run` 一致性
- [BatchPreflightService.cs](file:///Users/x/code/compress/Core/Services/BatchPreflightService.cs)：新增 `DecompressionPathStatus`、`DecompressionPathInspection` 与 `InspectDecompressionPath(string path)`，提供零磁盘副作用的统一单条目检验（缺失、解析异常、大小写歧义、重复分卷编号、缺首卷/不连续缺卷与合法首卷）。
- [BatchOperationService.cs](file:///Users/x/code/compress/Core/Services/BatchOperationService.cs)：新增 `FormatDecompressionIssue(DecompressionPathInspection, string)` 统一本地化阻塞问题提示。
- [GuiPreflightService.cs](file:///Users/x/code/compress/Core/Services/GuiPreflightService.cs) 与 [DecompressionItemAdapter.cs](file:///Users/x/code/compress/Core/Services/Pipeline/DecompressionItemAdapter.cs)：删除重复 `ArchiveVolumeResolver.Resolve` 校验分支，复用 `BatchPreflightService.InspectDecompressionPath` 与 `BatchOperationService.FormatDecompressionIssue`。
- [HeadlessBatchRunner.cs](file:///Users/x/code/compress/HeadlessBatchRunner.cs)：完善 `RunDryRun()` 的 `!_options.Compress` 分支，遇到缺卷、重复分卷或大小写歧义时输出对应诊断信息并返回退出码 `2`，全程零目录创建与磁盘写入。

### 2.2 全仓按卷路径比较收口
- [ArchiveVolumeResolver.cs](file:///Users/x/code/compress/Core/Services/ArchiveVolumeResolver.cs)：`ResolveOutputFiles` 改用 `VolumeAwarePathComparer.Instance` 去重，保留区分大小写卷上的大小写变体。
- [BatchOperationService.cs](file:///Users/x/code/compress/Core/Services/BatchOperationService.cs)：`LoadFilesFromTextFileWithDiagnostics`（密码本去重）、`LoadCompressionPathsFromTextFile` 与 `ReportPreflightFailure`（涉及来源列表去重）统一切换至 `VolumeAwarePathComparer.Instance`。
- [CliCommandBuilder.cs](file:///Users/x/code/compress/Core/Services/CliCommandBuilder.cs)：在判断 `TempDirectory` 是否与 `OutputPath` 一致时结合 `SourceCollector.NormalizePath` 与 `VolumeAwarePathComparer.Instance`，避免不区分大小写卷上的同路径因大小写差异误生成冗余 `--temp-dir`。
- [RarArchiveEngine.cs](file:///Users/x/code/compress/Core/Services/RarArchiveEngine.cs)：`IsUnderBaseDirectory` 改为遵循所在卷大小写敏感语义与目录分隔符前缀对齐校验。
- 注：保留 `SourceCollector.CollectCompressionSources` 与 `CollectDecompressionEntries` 的字面去重（`StringComparer.Ordinal`），确保显式列举的 `A.txt` / `a.txt` 在下游能被 `BatchPreflightService` 明确检测并报告输出冲突而非静默吞并（由既有 `TestBatchPreflightSafety` 锁定）。
