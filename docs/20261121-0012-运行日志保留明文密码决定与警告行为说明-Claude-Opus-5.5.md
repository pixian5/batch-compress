# 运行日志保留明文密码决定与警告行为说明

> 时间：2026-11-21 00:12　版本：`0.8.20 → 0.8.21`　模型：Claude Opus 5.5

## 一、用户决定：运行日志显示明文密码（2026-11-21 再次确认）

**决定**：运行日志（`logs/batchcompress_*.log`）与界面命令日志**保留明文密码，不脱敏**。7zz/RAR 命令行中的 `-p<密码>`、`-hp<密码>` 原样写入。

- 理由：日志用于本机诊断，需要看到实际传给归档程序的密码，才能排查“密码错误”“文件名密码算错”等问题。
- 这与早期既定策略“命令日志含密码不脱敏”一致（见 `20261116-0018-批次21至26详细设计方案-Claude-Opus.md`），本次分析曾建议改为脱敏，用户否决。
- **保持脱敏的地方不变**：导出诊断包、结果报告（CSV/Markdown）、NDJSON 输出仍经 `CredentialRedactor` 脱敏，因为它们用于对外分享。
- 现有保护：日志文件权限为 0600，只有当前用户可读。
- 注意：把运行日志直接发给别人时会泄露密码；需要分享时请用“导出诊断”。
- 以后的修改**不得**在写运行日志时调用 `CredentialRedactor`。

## 二、没开删除/移动时，归档警告是什么

> **0.8.22 已变更**：压缩返回码 1 现在直接算失败，本节表格只适用于 0.8.21 及以前，见 [v0.8.22 完成报告](20261121-0029-v0.8.22压缩不完整直接判失败-Claude-Opus-5.5.md)。

场景：7zz/RAR 返回码 1（例如有文件无读权限，没压进归档），且没有开启“删除源/移动源”。

| 位置 | 显示内容 |
| --- | --- |
| 命令行终端 | 只有汇总 `Success=1, Failed=0, PostProcessFailed=0`，退出码 **0**，没有警告字样 |
| 界面 | 条目显示“成功”；命令输出区能看到 7zz 原始 stderr（`WARNING: Cannot open 1 file`、`errno=13 : Permission denied`），但不标红 |
| 运行日志 | 7zz 原始警告，加一条 `[WARNING] Archive tool returned warnings (exit code 1) for <条目>; the archive may be missing files. No post-process configured, item counted as success.` |

也就是说，这种情况下来源文件完好（没有删除/移动），但归档可能不完整，用户只有看日志或命令输出才能发现。

### 本版改动

`0.8.20` 在这种情况下写的日志是 `post-process mode None skipped, sources kept`，读起来像“跳过了后处理”，容易误解。`0.8.21` 改为上表中的说法，开启删除/移动时的日志不变。代码位置：`Core/Services/Pipeline/BatchExecutionPipeline.cs` 的 `ApplyPostProcess`。

### 可选改进（未实施）

新增独立“警告”计数，让终端汇总和界面统计显示警告、命令行退出码非 0。需要同时改 NDJSON 契约（`schemas/ndjson-schema-v1.json`）、结果报告和界面，改动面较大，等用户决定。
