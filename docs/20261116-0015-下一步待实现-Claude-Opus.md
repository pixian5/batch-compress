## 批次 21（P0）全局异常兜底与崩溃日志

- **现状/证据**：`App.axaml.cs` 只有托盘与退出的局部 `catch`；`Program.Main` 无 `try/catch`；
  全仓库没有 `AppDomain.UnhandledException`、`DispatcherUnhandledException`、
  `TaskScheduler.UnobservedTaskException`。崩溃时日志只留到崩溃前的业务记录，没有堆栈。
- **目标**：界面线程、后台任务、进程级未处理异常都能落进现有日志文件，
  并给用户一个能照着做的提示（日志路径 + 诊断导出入口）。
- **改动点**：
  1. `Program.Main` 注册 `AppDomain.CurrentDomain.UnhandledException` 与
     `TaskScheduler.UnobservedTaskException`；后者记录后调用 `SetObserved()`，避免进程被带走；
  2. `App.OnFrameworkInitializationCompleted` 注册 Avalonia 的 `DispatcherUnhandledException`，
     记录后按情况把 `Handled` 设为 `true`（界面线程可恢复的场景），无法恢复时再交由进程兜底；
  3. 统一写日志：时间、线程、异常类型、消息、完整堆栈、当前版本、最近的业务阶段；
  4. 写日志本身要包一层 `try/catch`，日志系统自己出错时退回 `Console.Error`，绝不能在兜底里再崩。
- **验收**：人为制造三种异常（按钮回调里抛、后台任务里抛且不 await、进程级线程里抛），
  日志文件都能看到完整堆栈与版本；界面线程那个不会让应用直接消失。
- **风险**：不要在兜底处理器里做重活或弹复杂对话框，避免死锁；
  日志文件可能被占用，写失败要静默降级。
- **版本**：改产品源码，`+0.0.1`。

## 批次 22（P1）日志与报告容量上限、节流刷新

- **现状/证据**：`MainWindowViewModel.cs:436-452` 的 `_sourceFileList` / `_successLog` /
  `_failLog` / `_commandLog` 都是 `[ObservableProperty] string`，每次 `+=` 复制整段并全量刷新；
  全仓库无日志行数上限。`BatchReportCollector` 的 `List<BatchReportEntry>` 也无上限。
- **目标**：大批量任务下界面不卡、内存有界；日志内容与「含密码不脱敏」的既定行为保持不变。
- **改动点**：
  1. 每类日志设行数上限（建议 5,000 行），超出丢弃最旧并在顶部保留「已省略 N 行」标记；
  2. 追加改为 `StringBuilder` + 时间节流（建议 200 毫秒）合并刷新，空闲时再更新绑定属性；
  3. 报告收集器设上限（建议 20,000 条），超出只累计计数并标注「已省略」；
  4. 现有「清空某类日志」命令同时清空缓冲与省略计数。
- **验收**：模拟一万条任务，界面滚动与输入不卡顿、内存曲线有界；
  日志内容顺序与现有测试断言一致；清空、导出、诊断包行为不变。
- **风险**：节流刷新可能让最后几行延迟出现，批次结束时要强制刷一次；
  上限不能裁掉错误行优先保留策略——若做优先级，规则要写清。
- **版本**：改产品源码，`+0.0.1`。

## 批次 24（P2）本地化资源外置

- **现状/证据**：`LocalizationService.cs` 1,752 行，五种语言各一个约 290 行的 `Create*()` 方法；
  `LanguageStrings.cs` 364 行属性类。批次 14 只拆了命令行帮助。
- **目标**：词条外置为资源文件，加一种语言只需加一个资源文件 + 一行语言列表。
- **改动点**：迁移到 `.resx` 或 JSON（项目已引用 `System.Resources.Extensions`）；
  保留 `LanguageStrings` 作为强类型访问层；先用现有「界面本地化资源扫描」测试锁住键集合，
  再逐语言迁移，保证五语言键完全一致。
- **验收**：74 项测试全过（尤其「英文与德语资源不含中文」「界面本地化资源扫描」）；
  五语言界面人工各看一遍无空词条；新增测试语言只需加资源文件。
- **风险**：漏键会在界面上显示空字符串，测试必须先覆盖键集合再迁移；
  不要与 D6 的界面拆分混在同一批。
- **版本**：改产品源码，`+0.0.1`。

## 批次 25（P2）界面代码隐藏下沉 + 界面冒烟 3 条

- **现状/证据**：`Views/MainWindow.axaml.cs` 789 行；`测试夹具/` 只有按坐标点击与读屏幕尺寸的
  底层 Swift 小工具，没有可复跑的界面用例。
- **目标**：代码隐藏只保留纯视图事件转发；3 条界面冒烟可一键复跑。
- **改动点**：
  1. 缩放、窗口状态持久化、可下沉的拖放解析移到 ViewModel 或独立服务；
  2. 新增 `测试夹具/界面冒烟/`：启动后窗口存在、切一次语言标题变化、跑一个最小压缩任务并确认成功计数 1；
  3. 复用现有 `gui-click.swift` / `gui-screen.swift`，用固定窗口尺寸与相对坐标，避免分辨率耦合。
- **验收**：代码隐藏行数显著下降且 74 项测试零回归；3 条冒烟在本机一条命令跑完。
- **风险**：界面自动化容易受窗口位置/缩放影响，先固定窗口尺寸并在脚本开头复位；
  不要把冒烟做成阻塞交付的硬门禁，失败要能单独重跑。
- **版本**：改产品源码，`+0.0.1`。
