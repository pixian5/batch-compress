## 二、改动 1：移除当前目录 7-Zip 搜索

### 问题

`SevenZipArchiveEngine` 的 macOS/Linux 候选包含
`Directory.GetCurrentDirectory()/tools/7zip/.../7zz`，校验逻辑还会给候选补执行位并运行 `7zz i`。
用户在下载来的项目、临时目录或任何可写目录里运行命令行时，目录里的伪造 `7zz` 会被执行。

### 改法

- 删除当前工作目录候选；
- 生产只信任程序目录与系统安装位置；
- 需要自定义时用显式环境变量 `BATCHCOMPRESS_7ZZ_PATH`，它优先于所有默认位置；
- 新增源码守护测试：`SevenZipArchiveEngine.cs` 不得包含 `Directory.GetCurrentDirectory()`，
  且必须支持 `BATCHCOMPRESS_7ZZ_PATH`。

### 影响

- 正常安装/打包运行不受影响（程序目录与系统路径仍在候选里）；
- 开发时如果在仓库根目录依赖 `./tools/7zip/...`，需要改用程序输出目录或显式环境变量；
- 显式指定的路径仍按原有 `7zz i` 身份校验执行。

## 三、改动 2：诊断包、报告、NDJSON 共用密码脱敏

### 问题

诊断包已覆盖“引号包住整个参数”的形态，但结果报告仍用“`-p` 前必须是行首/空白”的旧正则；
NDJSON 只排除命令输出，对普通 `message` 不脱敏。三处规则不一致，一旦引擎把命令文本塞进错误消息，
报告或 JSON 可能带出密码。

### 改法

- 新增 `Core/Services/CredentialRedactor.cs`，把诊断包的脱敏规则收成唯一实现；
- `DiagnosticsExportService.RedactSensitiveText` 改为委托；
- 报告：用 `ContainsCredential` 判断，含凭据整条替换为 `[credential-redacted]`（沿用原策略）；
- NDJSON：所有 `message` 字段先过 `Redact`，保留上下文但把密码替换为 `***`；
- 覆盖 `-p` / `-hp` / `--password` 的常规、等号/冒号、空格、引号整体形态；
- 保留“命令输出整条排除”的第一道保证。

### 测试

- 共享脱敏：引号整体 `"-pSuper Secret 123"`、引号整体 `"--password=..."` 均被替换；
- 普通路径 `/tmp/-pictures/photo.jpg` 不被误伤，也不被判为凭据；
- 报告：含引号密码的消息整条变成 `[credential-redacted]`；
- NDJSON：输出中不再含明文密码，且出现 `-p***`。

## 四、改动 3：“随机密码”文案改为按文件名生成

### 问题

界面标签写“随机密码”，实际是按文件名加固定字符串做 MD5，同一文件名永远得到同一密码。
提示文字虽然写了“按文件名生成”，但主标签仍会造成“密码学随机”的误解。

### 改法

- 五语言标签改为“文件名密码 / File-name password / ファイル名パスワード / Dateiname-Passwort / 檔名密碼”；
- 提示文字补“兼容旧版，不是随机密码”；
- 命令行帮助里的“随机密码”改为“按归档文件名生成兼容密码”，选项名 `--random-password` 保持不变；
- **不改派生算法**，历史归档密码查询结果不变。

### 说明

这是文案诚实化，不是安全增强：真正随机密码需要另做显式模式和密码保存流程，未在本批实施。
