## 二、关键实测：错误到底从哪条流出来

没有靠猜。先构造了一个 3 MiB 随机数据的 1 MiB 分卷归档，篡改第二个分卷中间字节，
用官方 `7zz` 直接解压观察：

```
退出码=2
stdout: ... Sub items Errors: 1 / Archives with Errors: 1
stderr: ERROR: CRC Failed : big.bin
```

**结论：7-Zip 的 CRC（循环冗余校验）失败写在标准错误（stderr），标准输出只有汇总。**
而改造前 `ArchiveProcessRunner` 只对标准输出做逐行回调，标准错误是
`ReadToEndAsync()` 等进程结束才整段拿到——这就是「做不到提前终止」的根因。
所以本轮把标准错误也改成逐行流式读取。

## 三、实现细节

### 1. 解析器 `ArchiveSubProgressParser`

- 新增 `ArchiveFatalError`（分类 / 命中短语 / 原始输出行）与
  `ArchiveFatalOutputException`（与外部用户取消严格区分）。
- `TryParseFatalError` **只认 5 类明确的数据损坏**：CRC 失败、Data Error、
  归档意外结束、无法作为归档打开、分卷缺失。
- **保守策略**：刻意不认密码错误与普通警告——7-Zip 在某个条目密码错误时仍可能继续处理
  其它条目，误杀会中断整批。单元测试锁住了「进度行 / 汇总行 / Everything is Ok /
  WARNING / Wrong password」都不被误判。
- 解析回调抛异常时降级为「不提前终止」，绝不影响归档进程本身。

### 2. 进程边界 `ArchiveProcessRunner`

- `RunAsync` 新增可选 `onFatalLine` 回调；标准输出与标准错误都逐行检查。
- 命中后用**独立的联动取消令牌**终止当前进程（杀整棵子进程树），
  抛出 `ArchiveFatalOutputException`；外部用户取消优先，仍按原取消语义传播。
- 进程与取消同时自然退出的竞态也会补抛异常，避免漏判。
- **未传 `onFatalLine` 的路径（压缩、探测等）行为零漂移**。

### 3. 两个引擎与终端可见性

- `SevenZipArchiveEngine.ExtractAsync` 与 `RarArchiveEngine.ExtractAsync` 传入解析器，
  捕获异常转成失败结果（退出码 -4，错误消息带分类、短语、原始输出行），
  由执行管线走既有失败回滚与单独计数，**不会误当成功、也不会误触发关机**。
- `WinRarProcessRunner` 透传新参数（它本就复用通用进程执行器）。
- 顺带修复体验问题：默认模式下终端原本只有「1 failed」，具体原因只在日志里；
  现在失败消息会写标准错误，且不污染结构化输出（NDJSON，逐行 JSON）的 stdout。

### 4. 真实损坏分卷的端到端实测

`测试夹具/经验验证/verify.sh` 新增第 15 项：现场造分卷 → 篡改 → 用本项目命令行解压，
断言退出码 1、终端可见「归档损坏，已提前终止」、日志含 `CRC Failed`、输出目录零残片。

实测输出（关键点）：

```
[ERROR] Extraction failed: arc.7z.001 - 归档损坏，已提前终止：CRC 校验失败 — CRC Failed（ERROR: CRC Failed : big.bin）
Completed: Success=0, Failed=1, ...
输出目录：不存在（批次 13 的失败回滚生效）
```

从开始到失败约 57 ms，不再读完整个损坏分卷。

## 四、149 项端到端夹具接入持续集成

`ci.yml` 与 `release.yml` 的测试门禁各加一步（仅 macOS runner）：

```yaml
- name: 端到端全功能夹具（仅 macOS）
  if: runner.os == 'macOS'
  run: |
    chmod +x tools/7zip/macos/7zz
    zsh 测试夹具/全功能测试/run-all-tests.sh
```

显式用 `zsh` 是必须的：该脚本使用 `${0:A:h:h:h}` 与 `print` 等 zsh 专有语法，
用 `bash` 调用会报 `print: command not found` 且路径解析到根目录（上一轮踩过的坑）。
`chmod +x` 是为了云端检出后仍可执行仓库内的官方 `7zz`。

**更正上一轮报告的一处不准确说法**：批次 14 已经把 `scripts/smoke-test.sh`（三平台）
与 `测试夹具/经验验证/verify.sh`（macOS 门禁）接进了两个工作流；
本轮补的是**149 项端到端夹具**，不是这两项。云端的 YAML（工作流配置）改动
需推送后由 Actions 实际运行验证，本地已用同样的 zsh 命令跑过 `TOTAL PASS=149 FAIL=0`。
