## 一、交付内容

### 1. 新增 `Core/Services/CrashLogService.cs`

- `RegisterGlobalHandlers()`：幂等注册 `AppDomain.CurrentDomain.UnhandledException`
  与 `TaskScheduler.UnobservedTaskException`；后者记录后 `SetObserved()`，
  避免后台任务异常在回收时把进程带走。
- `Write(stage, exception, context)`：写阶段、版本、运行时、系统、架构、线程、
  异常类型与消息、完整堆栈。
- `WriteMessage(stage, message, context)`：非异常的致命诊断。
- **四条硬约束**：
  1. **去重**：同 `stage + 异常类型 + 消息前 120 字` 在 2 秒内只写一条，
     并累计抑制次数，下次写入附 `suppressed=N`；
  2. **自保护**：整体包 `try/catch`，连异常对象自己的 `ToString()` 也单独兜一层，
     最终失败退回 `Console.Error`，绝不在兜底里再崩；
  3. **权限**：Unix 上写完后设为 0600；先写 `.tmp` 再原子移动，避免半截日志；
  4. **容量**：`batchcompress-crash_*.log` 最多 20 个，写入后裁剪最旧。
- 文件名带毫秒、进程 ID 与进程内序号——同一毫秒连写多条不会互相覆盖。

### 2. 三处注册

| 位置 | 事件 | 策略 |
| --- | --- | --- |
| `Program.Main` 第一行 | `AppDomain.UnhandledException`、`TaskScheduler.UnobservedTaskException` | 记录；后者标记已观察 |
| `Program.Main` 外包 `try/catch` | 启动与运行期兜底 | 记录后返回退出码 1 |
| `App.OnFrameworkInitializationCompleted` | `Dispatcher.UIThread.UnhandledException` | 记录后 `e.Handled = true`，窗口尽量存活 |

`Program.Main` 拆成「注册 + try/catch 外壳」与 `RunCore(args)`，
原有解析/帮助/版本/无界面/GUI 分支逻辑整体搬进 `RunCore`，行为不变。
无界面路径的既有 `catch` 也追加写一份崩溃记录。

## 三、实施中发现并修掉的两个问题

1. **测试里的异常没有堆栈**：第一版测试用 `new InvalidOperationException(...)`，
   未抛出过的异常 `ToString()` 不含堆栈，断言「缺少堆栈」失败。
   改为 `try { throw ... } catch (Exception ex)` 捕获后再写，验证的才是真实场景。
2. **同一毫秒写入互相覆盖**：文件名原本只有毫秒 + 进程 ID，连续写入会落到同一文件名，
   后一条覆盖前一条，测试表现为「期望 3、实际 2」。已加进程内自增序号。
3. **界面层中文扫描**：`App.axaml.cs` 里崩溃上下文写成中文，
   被现有「界面本地化资源扫描」测试判为硬编码中文；改为英文短语
   `unhandled exception on UI thread`（内部诊断，不需要五语言）。
