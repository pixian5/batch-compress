## 二、评估清单逐项结论

按详细设计方案第 6 节的四项评估清单执行：

### 1. 11.0 的破坏性变更是否影响本项目

查到的官方变更主要有两类：

- **九个 Microsoft.Extensions 抽象库进入 .NET 11 共享框架**：显式引用会在 `net11.0` 及以上目标框架收到 NU1510 警告，建议移除包引用。本项目目标框架是 **`net10.0`**，这条不适用；实测构建 0 警告，没有触发 NU1510。
- **`Microsoft.Extensions.Logging` 内部类型迁移、兼容垫片标记过期**：主要影响日志库作者与 source generator。本项目只是自己实现 `ILogger` 与 `ILoggerProvider` 两个稳定接口（`FileLoggerService` / `FileLoggerProvider`），没有引用内部类型；全量重编译零警告，说明没有命中过期垫片。

另有 DI 抽象层的行为调整（如 `ActivatorUtilities` 一致性），本项目不直接使用这些 API。

### 2. 包可用性与目标框架资产

用项目内临时探针在 `net10.0` 下解析 11.0.0 三个包，还原成功、无 NU1202 一类不兼容提示。包内提供 `net10.0`、`net11.0`、`net462`、`netstandard2.0/2.1` 多套资产，因此 net10.0 项目可以正常选用对应资产。

**依赖变化**（升级后实际解析，`dotnet list package` 确认）：

| 范围 | 升级前 | 升级后 |
| --- | --- | --- |
| 主工程顶层三个包 | `10.0.14` | `11.0.0` |
| 测试工程 `Logging.Abstractions` | `10.0.14` | `11.0.0` |
| 传递依赖（Configuration / DI / Options / Primitives / Logging.Abstractions 等） | `10.0.14` | `11.0.0` |
| 基础库（System.Text.Json、System.IO.Pipelines、System.Collections.Immutable 等） | 随运行时 | 随包升到 `11.0.0` |

设计方案担心的「与 Avalonia 12.1.6 依赖树冲突」没有发生：Avalonia 的依赖树不引用 Microsoft.Extensions.*，两条链互不干扰。

### 3. 四项重点验证

| 重点 | 验证方式与结果 |
| --- | --- |
| 日志文件格式与现有解析兼容 | 真实产物跑带密码压缩：日志服务产生的 **26/26 行**仍是 `[时间戳] [级别] [操作] 消息` 格式；文件权限 **0600**；按既定策略保留明文密码。原因：日志行由 `FileLoggerService.Log` 自己拼接，不依赖日志库的默认格式化器，11.0 的格式变化影响不到这里 |
| 多代轮转、Gzip、保留期清理 | 81 项单元测试中的「日志权限与轮转」「日志多代轮转」「日志旧代Gzip压缩」「日志压缩异常降级兜底」「日志自定义保留期清理」全部通过（`.1` 纯文本、`.2+` Gzip、异常降级、保留期策略） |
| 诊断导出解包 `.gz` 并脱敏 | 专项验证造了一份含明文密码的 Gzip 轮转日志，导出诊断包后确认：包内 3 项，`.gz` 被解包成可读文本（明文标记可见），`-p` 密码被替换为 `***`，两个明文口令均不出现在包内；「安全诊断日志脱敏导出」测试也通过 |
| `ILogger` 注入链无变化 | 全量重编译零警告；`BatchOperationService`、执行管线、后处理服务、适配器全部使用可空的 `ILogger?`，自定义 `ILogger` / `ILoggerProvider` 实现与新接口形状一致；相关管线、NDJSON、并发测试全过 |

专项验证共 10 项，全过（日志格式、0600 权限、明文密码保留、NDJSON 逐行合法 JSON、NDJSON 不含密码、CSV 报告含逐项、CSV 不含密码、Gzip 解包、密码脱敏、脱敏标记）。

> 专项脚本第一次跑出 3 项 FAIL，排查后确认是我把日志文件命名成了 `batchcompress.log.2.gz`，而诊断导出只收集 `batchcompress_*.log*`（下划线前缀），属于探针命名假设错误；改正命名后 10 项全过，与依赖升级无关。

## 五、遗留风险（不阻塞）

1. **仅在 macOS（Apple Silicon）实机验证**。项目另有 Windows 10 与 Debian 13 机器，11.0.0 的 net10.0 资产在这两个平台未实机跑过。按用户决定，本项目是本地应用，交付与验证以本机完成、不依赖云端矩阵；如以后需要三平台确认，可在那两台机器上各跑一次构建与夹具。
2. **传递依赖整体升到 11.0.0**，包含 System.Text.Json 等基础库在 net10.0 运行时上的 11.0 版本。本机已验证本地化资源加载、NDJSON 输出、报告写出、诊断导出都正常，但这是一次较大范围的依赖面变化，后续若在别的机器出现奇怪的序列化问题，优先回看这一条。
3. **单文件自包含发布体积**约 111 MB；本次没有记录升级前的精确基线，不做体积结论。
